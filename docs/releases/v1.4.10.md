# VibeMeters v1.4.10

장시간 Windows 잠금 후 Claude 인증 복구와 로그인 안내를 개선했습니다.

- 인증 갱신 확인 중·재시도 대기·확정 재로그인 필요를 구분하고, 복구 중에는 이전 수치를 숨깁니다.
- 공식 CLI 작업을 설정 경로별로 공유합니다. 최초 CLI 대기는 12초, 이미 진행 중인 작업은 2초이며 인증 파일 반영을 최대 8초 더 확인합니다. 새 토큰·미래 만료와 실제 사용량 조회 성공까지 확인합니다. 상태 명령 성공만으로 갱신을 보장하지 않습니다.
- 명시적으로 로그인 버튼을 눌러도 먼저 기존 인증을 확인합니다. 복구되었거나 요청 제한·알려진 인증 작업 진행 중이면 브라우저 로그인을 열지 않습니다. 429/Retry-After와 일반 서버 보호 대기는 유지합니다.
- 토큰·계정·CLI 원문을 제외한 원인 enum·종료코드·변경/미래만료 bool만 로컬 진단에 기록합니다. 현재/보관 파일 2개를 사용하고, 64KiB 이상에서 다음 기록 전 회전하므로 한 행 초과가 가능합니다. 마지막 수정 7일 지난 파일은 다음 기록 시 정리하며 개별 행의 보존 기한을 보장하지 않습니다.

CLI는 토큰 저장 보호를 위해 대기 취소·시간 초과 때 강제 종료하지 않습니다. 끝나지 않은 CLI는 후속 복구에서도 공유되므로 공식 CLI 상태를 직접 확인해야 할 수 있습니다. 완료된 작업은 설정 경로별 표에 다음 요청까지 유지합니다. 실제 장시간 잠금 후 토큰 회전은 이번 릴리스 절차에서 재현하지 않았습니다.

ZIP 전체를 새 폴더에 압축 해제하고 EXE·runtime·문서를 함께 유지하세요. 기존 설정은 보존됩니다. 이번 배포 검증은 최종 커밋의 Release self-contained 빌드·패키징, 무계정 Gemini 진단과 ZIP/원격 asset 무결성 확인입니다. 회귀·전체 UI 스모크·실계정·CLI 설치·현재 앱 교체는 생략했습니다. 이전 구현/로컬 적용 증거는 [VERIFICATION.md](https://github.com/Nectarine-Peach/VibeMeters/blob/v1.4.10/VERIFICATION.md)에 구분했으며 기존 이미지는 이전 버전의 합성 캡처입니다.

<summary>English release notes</summary>

Claude recovery now distinguishes checking, retry waiting and confirmed sign-in required, and hides stale quotas while authentication is unresolved. Official CLI work is shared per configuration directory. The initial CLI wait is 12 seconds (two seconds for shared work), followed by up to eight seconds for credential-file propagation. A changed, unexpired token and a successful usage request are required; a successful status command alone does not guarantee renewal.

An explicit Login action first checks existing authentication. It skips browser sign-in when recovered, rate limited or waiting for known running renewal work. Rate-limit/Retry-After and general server protection remain in force. A CLI is not terminated on timeout or cancellation, so a command that never exits may require manual investigation. Completed tasks stay in the per-config table until the next recovery request replaces them.

Local diagnostics contain only closed reasons, exit codes and change/expiry booleans, excluding tokens, accounts and raw CLI output. Current and archive files rotate before an append after reaching 64KiB (one row of overshoot is possible). Files last modified over seven days ago are removed on the next write; individual rows have no guaranteed retention deadline.

Extract the entire ZIP and retain runtime and documentation. This publication checks final-commit Release packaging, account-free Gemini diagnostics and archive/remote asset integrity. Regression/full UI smoke, live account checks, CLI installation and local app replacement were skipped. Earlier implementation evidence is recorded separately; included images are synthetic captures from earlier versions.
