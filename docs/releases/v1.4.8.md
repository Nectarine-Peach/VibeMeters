# VibeMeters v1.4.8

Claude 인증 만료 시 이전 비율이 계속 보이던 문제를 개선했습니다.

- 만료 또는 HTTP 401 때 설치된 공식 Claude Code **2.1.301 이상**의 비대화형 `auth status`로 인증 갱신을 한 번 시도합니다. 앱은 refresh token을 직접 교환하거나 인증 파일을 쓰지 않습니다.
- 인증 파일에서 교체된 토큰과 미래 만료를 확인한 경우에만 사용량을 다시 요청합니다. 갱신 실패·권한 오류·연결 해제 때는 이전 Claude 비율을 숨기고 로그인 버튼을 표시합니다. 기존 429 대기는 유지합니다.
- 한국어·영어 안내와 계정 지원 문서를 갱신했습니다. 자동으로 로그인 브라우저나 모델 요청을 실행하지 않습니다.

CLI 대기는 45초입니다. 토큰 저장을 보호하기 위해 실행 중인 CLI를 강제 종료하지 않으며, CLI가 끝나지 않으면 추가 자동 갱신도 보류됩니다. 이 경우 공식 CLI 상태를 확인하고 필요하면 직접 다시 로그인하세요. 실제 만료 토큰의 회전 성공은 이번 배포에서 재현하지 않았습니다.

기존 앱을 트레이에서 종료하고 ZIP 전체를 새 폴더에 압축 해제하세요. EXE·runtime·README·docs를 함께 유지하며 기존 설정은 보존됩니다. 이번 배포 검증은 Release self-contained 컴파일·패키징, 계정 없는 Gemini 진단 및 ZIP/원격 asset 무결성 확인입니다. 회귀·전체 UI 스모크·실계정·CLI 설치와 현재 앱 교체는 실행하지 않았습니다. 이전 구현 단계의 검증 기록은 [VERIFICATION.md](https://github.com/Nectarine-Peach/VibeMeters/blob/v1.4.8/VERIFICATION.md)에 별도로 구분했습니다.

<summary>English release notes</summary>

Claude authentication failures now hide stale percentages and show an explicit sign-in action. For expired credentials or HTTP 401, VibeMeters tries the installed official Claude Code **2.1.301+** noninteractive `auth status` once. Only a changed token with a future expiry enables a usage retry. The official CLI owns credential rotation and storage; VibeMeters never exchanges refresh tokens or writes credential files. Existing HTTP 429 cooldowns remain in place.

The app waits up to 45 seconds and does not terminate a running CLI during credential storage. A CLI that never exits blocks further automatic renewal; check the official CLI and sign in manually if needed. Browser sign-in and model requests never start automatically. Actual expired-token rotation was not reproduced for this release.

Extract the entire ZIP into a new folder and retain runtime and documentation. Existing settings are preserved. This publication checks Release self-contained packaging, the account-free Gemini diagnostic and archive/remote asset integrity. Regression/full UI smoke, live account checks, CLI installation and local app replacement were skipped. Earlier implementation verification records are identified separately in VERIFICATION.md.
